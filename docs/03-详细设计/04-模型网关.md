## 1 槽位

五个槽位，按用途命名而非按厂商。系统内部只认槽位名。

| 槽位         | 用途         | 典型配置                         |
| ---------- | ---------- | ---------------------------- |
| `main`     | 答案生成       | DeepSeek `deepseek-chat`     |
| `fallback` | `main` 失败  | 百炼 `qwen-plus`               |
| `aux`      | 意图理解、结构化抽取 | 百炼 `qwen-flash`              |
| `embed`    | 文本向量       | 硅基 `BAAI/bge-m3`（1024 维）     |
| `rerank`   | 证据重排       | 硅基 `BAAI/bge-reranker-v2-m3` |

## 2 一次调用

```text
取知识指纹 → 查缓存 → 预算裁剪 → 按槽位顺序试 → 成功即返回并记账
```

| 顺序 | 动作 | 失败后 |
| --- | --- | --- |
| 1 | 命中 L1 缓存直接返回，记 `cached=true` | — |
| 2 | 超日预算时只保留最便宜的一档 | 硬停配置生效则整条链放弃 |
| 3 | 按链逐槽位调用，每槽位内重试 | 该槽位失败则熔断计数 +1，换下一槽位 |
| 4 | 成功后写入缓存、记台账 | — |
| 5 | 全链失败抛 `AllProvidersFailed` | 能力层转 `ungrounded` |

## 3 重试与超时

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `GW_RETRY_MAX` | 3 | 单槽位最多尝试次数 |
| `GW_RETRY_INITIAL` | 0.5s | 退避起始倍数，指数加抖动，上限 8s |
| `GW_TIMEOUT_CONNECT` | 3s | 建连 |
| `GW_TIMEOUT_CHAT` | 60s | 非流式整次调用 |
| `GW_TIMEOUT_FIRST_TOKEN` | 20s | 流式首个 token |
| `GW_TIMEOUT_STREAM` | 120s | 流式整体 |
| `GW_TIMEOUT_EMBED` | 30s | 向量 |
| `GW_TIMEOUT_RERANK` | 20s | 重排 |
| `GW_MAX_CONCURRENCY` | 8 | 同时在途请求上限 |

重试只发生在三类错误上：请求超时、上游 5xx、429 且 `Retry-After` 不超过 10 秒。其余 4xx（密钥错、模型不存在、欠费、额度耗尽）不重试，直接换槽位。

流式一旦开始吐字就不再重试：重试会把已输出内容再说一遍，只能抛 `StreamInterrupted`。

## 4 熔断

按槽位独立计数，互不影响。

| 参数 | 值 |
| --- | --- |
| 失败阈值 | 60 秒窗口内 5 次 |
| 打开后冷却 | 60 秒 |
| 恢复条件 | 冷却后连续 2 次成功即清除打开标记 |

熔断打开时该槽位直接跳过，计入错误列表但不发请求。`embed`、`rerank` 熔断打开时对应能力退化为不可用。

## 5 缓存

三级，key 都含模型名，避免换模型后读到旧结果。

| 级 | 内容 | TTL |
| --- | --- | --- |
| L1 | chat 结果，key 含 messages、参数、知识指纹 | 86400s，降级 600s |
| L2 | 单条文本的向量，区分 `doc` / `query` | 2592000s |
| L3 | 查询与候选集的重排结果 | 604800s |

知识指纹 = `published` 文档数 + 最新发布时间，缓存 60 秒。发布或回滚时主动删除，旧答案不会在换版后继续命中。

chat 只做精确匹配，不做语义相似：同一问句在不同模板或不同身份下答案本就不同。

## 6 预算

| 参数 | 值 |
| --- | --- |
| `GW_DAILY_BUDGET_CNY` | 20 元/日 |
| 计数方式 | Redis `INCRBY` 微元整型，按自然日分键 |
| 超预算 | 调用链裁剪为最便宜的一档，结果标降级 |
| `GW_BUDGET_HARD_STOP` | 为真时超预算直接拒绝，不再调用 |

## 7 台账

每次模型调用一行 `ai_calls`，进程内缓冲后批量写入，不占主链路。

| 字段组 | 内容 |
| --- | --- |
| 标识 | `trace_id`（UUID）、任务类型、槽位、模型名 |
| 结果 | 状态、尝试次数、是否缓存、是否流式 |
| 用量 | 输入/输出 token、费用（微元折算） |
| 耗时 | 总耗时、首 token 耗时 |

台账是成本与延迟指标的唯一来源；写入失败只丢这一批，不影响问答。

## 8 覆盖配置

`model_settings` 表按槽位覆盖 `base_url` 与模型名，运营界面修改，30 秒内生效。

密钥始终只在环境变量里，接口与页面都不读写密钥。

## 9 故障注入

开发环境可用 `fault_inject --provider <槽位> --mode <timeout|error500|...> --ttl <秒>` 给指定槽位挂故障，写入 `gw:fault:{slot}`，网关调用前读取。

仅 `GW_FAULT_INJECTION=true` 时生效，用于降级演练。

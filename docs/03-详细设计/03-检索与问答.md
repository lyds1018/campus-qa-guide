## 1 链路

单轮作答固定六步，每步独立可测，串联只做编排。

```text
理解 → 检索 → 门槛 → 事项与槽位 → 生成 → 校验
```

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 理解 | 问句、身份、历史 | 意图、改写后问句、子问题、缺失信息 |
| 检索 | 改写后问句、文档类型过滤 | 证据块（含编号、分数、来源） |
| 门槛 | 检索结果 | 可答 / 拒答原因 |
| 事项与槽位 | 问句、证据 | 事项匹配、槽位、清单、提示 |
| 生成 | 提示消息 | 答案正文 |
| 校验 | 正文、证据、冲突 | 校验报告、引用列表 |

## 2 理解

主路径是 aux 槽位一次结构化调用，失败退规则。规则不是备用方案，而是口径兜底。

| 项 | 口径 |
| --- | --- |
| 意图 | `matter` / `policy` / `faq` / `smalltalk` / `out_of_scope` |
| 改写 | 词典别名替换为规范名，模型输出后再套一遍词典 |
| 身份 | `undergrad` / `grad` / `staff` / `alumni` / `unknown`，请求带身份时以请求为准 |
| 子问题 | 最多 3 条，去重、去与原问句相同的项 |
| 缺失信息 | 事项/制度类问句命中词少于 2 个时补「具体事项名称或办理环节」 |

越界以规则为准：规则判为 `out_of_scope` 且模型未判 `smalltalk` 时，一律按越界处理。

寒暄与越界不检索、不生成，直接返回固定文案。

## 3 检索

```text
向量召回 top-20  ┐
                 ├→ RRF 融合 → 保留 25 → 重排 → 定门槛
全文召回 top-20  ┘
```

| 环节 | 参数 | 说明 |
| --- | --- | --- |
| 向量召回 | `QA_TOP_K_VECTOR=20` | 余弦距离，只查 `published` 块 |
| 全文召回 | `QA_TOP_K_FTS=20` | jieba 词 OR 组合成 tsquery |
| 融合 | `QA_RRF_K=60`、`QA_FUSE_KEEP=25` | 分数 = Σ 1/(k+排名)，归一化到 [0,1] |
| 重排 | `QA_EVIDENCE_TOP=6` | 交叉编码器打分，取门槛一半以上的前 6 条 |
| 字符预算 | `QA_MAX_EVIDENCE_CHARS=6000` | 按分数从高到低装入，装不下即止 |

降级：embedding 不可用时只走全文；重排不可用时用融合分排序。两条降级路径都不改变对外结构，只在 `notes` 里记一笔。

## 4 可答门槛

判定只用绝对量。融合分只表达排名，全库带向量时必然为 1.0，不能当相关度。

| 条件 | 阈值 | 触发 |
| --- | --- | --- |
| 有重排 | 最高重排分 ≥ `QA_MIN_RERANK_SCORE=0.35` | 低于则 `low_confidence` |
| 无重排 | 最高余弦 ≥ `QA_MIN_VECTOR_SIM=0.58` 或 命中词数 ≥ `QA_MIN_FTS_OVERLAP=2` | 都不满足则 `low_confidence` |
| 无证据 | 候选为空 | `no_evidence` |

## 5 事项与清单

事项匹配优先查表，查不到再由召回文档标题派生。

| 来源 | 条件 | 用途 |
| --- | --- | --- |
| 事项库 | 事项名包含在问句中，或字面重合 ≥ 0.8 | 结构化步骤与材料 |
| 派生 | 无表命中 | 用召回文档标题充当事项名 |

清单三类，只从与命中事项同标题的块里抽；没有同标题块时取证据前三块。

| 类型 | 识别小节 |
| --- | --- |
| `material` | 所需材料、申请材料、提交材料 |
| `step` | 办理流程、办理步骤、申请流程 |
| `condition` | 办理条件、受理条件、申请条件、适用对象 |

条目只认有序号的行（`1.` / `①` / `一、` / `第N步`），单条截断 160 字，同类最多 10 条。注意事项类小节不进清单。

槽位抽取规则化：身份、渠道、紧急度来自词典与关键词，不交给模型。

## 6 生成

| 项 | 口径 |
| --- | --- |
| 槽位 | `main` |
| 提示结构 | system 固定规则 + user（问句、身份、证据、事项、槽位、冲突） |
| 参数 | `QA_ANSWER_TEMPERATURE=0.2`、`QA_ANSWER_MAX_TOKENS=900` |
| 引用写法 | 证据以 `[1]` `[2]` 编号，要求逐句标注 |
| 归一化 | 统一引用锚、去掉模型自带的 Markdown 标题与加粗 |

冲突存在时提示要求并列说明两种说法，不允许取其一。

## 7 校验

| 检查 | 规则 | 阻塞 |
| --- | --- | --- |
| 引用存在 | 正文至少出现一个 `[n]` | 是 |
| 引用有效 | 编号在 1 至证据条数之间 | 是 |
| 数值可核 | 正文中的「数值+单位」必须出现在证据里，中文数字与阿拉伯数字互认，`块`/`元`、`个工作日`/`工作日` 归一 | 是 |
| 引用覆盖 | 含数字、材料、地点、费用、时限等硬信息的句子，带引用比例 ≥ `QA_MIN_CITATION_COVERAGE=0.6` | 是 |
| 冲突并列 | 检测到的口径冲突值必须在正文出现 | 是 |

冲突检测只比同事项（标题字面重合 ≥ 0.6）的费用与时限，跨事项不比较。

阻塞项三条（无引用、引用越界、数值不可核）为硬失败：同步路径允许一次修复重写，仍不过则转 `ungrounded` 拒答；流式路径已在吐字，不重写，直接标未核实。

## 8 拒答口径

| 原因 | 触发点 | 对外表述 |
| --- | --- | --- |
| `empty_question` | 问句为空 | 提示输入问题 |
| `too_long` | 超过 200 字 | 提示精简 |
| `out_of_scope` | 意图越界 | 说明只答校内事务 |
| `no_evidence` | 检索无候选 | 说明知识库未收录，给出可查部门 |
| `low_confidence` | 未过门槛 | 给出最高分与门槛，说明依据不足 |
| `ungrounded` | 硬失败或模型全不可用 | 列出可核对原文，说明未通过核对 |

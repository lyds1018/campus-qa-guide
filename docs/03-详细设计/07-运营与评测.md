## 1 上传到发布

```text
上传 → 暂存区 → 建任务 → 队列 → 解析入库（草稿）→ 审核 → 发布
```

| 步骤 | 落点 | 说明 |
| --- | --- | --- |
| 上传 | `var/uploads/{checksum12}/{原名}` | 限后缀与 20MB，先落本地再进对象存储 |
| 建任务 | `ingest_jobs` | 与命令行入库共用同一张表与同一条流水线 |
| 消费 | worker | 失败可在页面重试，重试复用同一任务记录 |
| 审核 | 待审列表 | 展示草稿标题、块数、与在版版本的数值冲突 |
| 发布 | 版本状态机 | 见 `02-知识入库` §6 |

草稿在审核期间不影响线上检索：检索只读 `published`。

## 2 口径冲突

审核页对新草稿做一次与在版文档的数值比对。

| 项 | 口径 |
| --- | --- |
| 比对对象 | 同事项文档（标题字面重合 ≥ 0.6） |
| 比对字段 | 费用（`X 元/份`、`每份 X 元` 两种写法）、时限（`X 个工作日`） |
| 触发 | 两侧取值不同 |
| 新稿自相矛盾 | 新稿内部已有多种说法时不报，交编辑先理清 |
| 输出 | 字段、草稿值、在版值、在版文档名与 id |

冲突只是提醒，不阻止发布。

线上作答另有同口径的检查：检测到冲突必须并列说明，否则校验判失败。两处实现独立，一个服务审核流程，一个服务线上问答。

## 3 运营看板

| 指标 | 口径 |
| --- | --- |
| 文档 / 块 / 事项 | 按状态分组计数 |
| 队列积压 | Redis 列表长度 + 各状态任务数 |
| 问答量 | 时间窗内 assistant 消息数 |
| 拒答率 | `answerable=false` 占比 |
| P50 / P95 | 时间窗内 `messages.latency_ms` 分位 |
| 意图分布、拒答原因分布 | 按 `intent`、`refusal_reason` 分组 |

看板与评测页共用同一套统计口径，定义集中在 `orchestrator/stats.py`。

## 4 评测对象

评的是能力层 `qa.answer()`，不是会话层 `orc.turn()`。会话状态与 SSE 装配不在评测范围，跑批也不写 `messages`。

跑批与演练只走命令行，HTTP 只提供只读的历史查询。

## 5 回归

黄金集在 `apps/qa/fixtures/golden.jsonl`，每行一条：问句、期望意图、应可答或应拒答、期望命中文档、必须出现的关键词。

| 指标 | 定义 |
| --- | --- |
| `hit@3` | 期望文档出现在证据前三 |
| `must` | 关键词全部出现在答案里；拒答题不参与 |
| 可答判对 | 应可答的题确实作答 |
| 拒答判对 | 应拒答的题确实拒答 |
| 引用覆盖 | 答案至少带一条引用 |
| 校验通过 | 无阻塞校验项 |
| P50 / P95 | 单题端到端耗时，分冷缓存与热缓存两栏 |
| 成本 | 跑批窗口内 `ai_calls.cost` 之和 |

达标线：前四项与校验通过 ≥ 90%，引用覆盖 ≥ 70%。低于线写进报告的未达标栏。

报告为 Markdown，落 `EVAL_REPORT_DIR`；每次跑批在 `eval_runs` 留一行档案。

## 6 演练

固定五个场景，取黄金集前若干条，判行为不判答对率。

| 场景 | 注入 | 期望 |
| --- | --- | --- |
| `baseline` | 无 | 作为对照 |
| `embed_down` | 嵌入 500 | 退纯全文召回，仍可作答 |
| `rerank_down` | 重排 500 | 用融合分截断，仍可作答 |
| `main_timeout` | 主模型超时 | 降级到备用槽位，结果标 `degraded` |
| `chat_all_down` | 主备都失败 | 给原文出处或明确拒答 |

失败口径两类：应拒答却作答；应作答却既没答也没给兜底出处。优雅降级不算失败。

演练期间必须关闭 L1 缓存，否则请求不发出去，故障不会触发。

## 7 反馈闭环

| 环节 | 口径 |
| --- | --- |
| 采集 | 学生端对答案点「有用 / 没用」，可选原因：口径错、答不全、答非所问、过期、其他 |
| 归档 | `feedback` 表记问句、答案摘要、评分、原因、`trace_id` |
| 标注 | 运营补 `expect`（应可答 / 应拒答 / 说不清） |
| 转黄金集 | `p7_golden` 默认只打印候选；`--apply` 才追加，按问句去重并标记已处理 |

反馈不进黄金集全靠人工确认，避免把噪声当基线。

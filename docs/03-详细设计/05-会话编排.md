## 1 一轮流程

```text
载入会话 → 指代补全 → 理解 → 路由 → 执行（单段 / 并行）→ 装配 → 落库
```

会话不存在或 id 与身份不匹配时新建，不报错。

## 2 路由

| 模式 | 触发 | 行为 |
| --- | --- | --- |
| `direct` | 意图为寒暄或越界 | 不检索、不生成，直接回文案 |
| `single` | 其余情况 | 一段作答，流式走真流式 |
| `fanout` | 子问题 ≥ 2 条 | 并行作答，统一装配 |

子问题上限 `ORC_FANOUT_MAX=3`。只有一段时不用 fanout，避免多花一次调用。

## 3 指代补全

| 条件 | 处理 |
| --- | --- |
| 上一轮有事项名 | 作为补全候选 |
| 问句含「这个 / 那个 / 该事项 / 它 / 这项 / 上面说 / 刚才说 / 那要」 | 视为回指 |
| 问句 ≤ 10 字 | 把上一轮事项名拼到问句前 |
| 问句 > 10 字 | 视为新话题，不补 |

补全发生在检索之前，因为它决定检索用的字符串。

## 4 执行与兜底

| 项 | 口径 |
| --- | --- |
| 单段超时 | `ORC_SEGMENT_TIMEOUT=25s` |
| 段失败 | 返回兜底答案，`answerable=false`，提示稍后重试或查原文 |
| 并行 | 子问题之间无依赖，同时发起，`trace_id` 共用同一个 |
| 部分失败 | 保留成功段，`failed_segments` 计数，另发一条提示 |

能力层已经处理「模型挂了给原文」，编排层这一道防的是能力层自身异常或卡死。

## 5 装配

多段不是文本拼接，三样东西都要合并：

| 对象 | 规则 |
| --- | --- |
| 正文 | 多段按 `①②③` 编号分段，段间空行 |
| 引用 | 按 `chunk_id` 去重，记录该引用出现在第几段 |
| 清单 | 按条目文本去重，重新连续编号，保留来源段 |
| 提示 | 多段时前缀「第N段：」 |
| 状态位 | `answerable` 取任一段为真；`degraded` 取任一段为真 |

流式与并行共用同一套装配，唯一区别是流式结果在 `meta` 里标 `stream=true`。

## 6 SSE 事件

| 事件 | 载荷 | 时机 |
| --- | --- | --- |
| `session` | `conversation_id`、`turn` | 首帧，先于一切处理 |
| `stage` | `stage`：`understand` / `route` / `fanout` / `generate` | 阶段切换 |
| `delta` | `text` | 增量文本，可多次 |
| `answer` | 整份 `TurnResult` | 生成结束 |
| `notice` | `level`、`text` | 降级、部分失败、口径冲突 |
| `error` | `message` | 致命错误 |
| `done` | `conversation_id`、`turn`、`latency_ms`、`trace_id` | 收尾，出错也发 |

帧格式为 `event:` 行 + `data:` 行 + 空行。不用 `id`、不用 `retry`。静默超过 15 秒插入注释心跳 `: ping`。

流式只有 `single` 是真流式；`fanout` 边算边拼会让首字变慢，整段吐出。

## 7 会话状态

Redis 只放下一轮要用的东西，PG 存留痕。

| 存储 | 内容 |
| --- | --- |
| Redis `orc:sess:{id}` | 最近 6 轮问答、槽位、上一轮事项与意图，TTL 1800s |
| PG `messages` | 每轮问句与答案、整份 `TurnResult` |

Redis 丢失时从 `messages` 最近 12 条重建上下文窗口，丢掉的只有「上一轮事项」这类快捷字段，指代能力随之退化一轮。

答案正文只存首 200 字进 Redis 窗口；完整答案在 `payload` 里。

## 8 落库

| 表 | 写入时机 |
| --- | --- |
| `conversations` | 首轮创建；每轮更新 `turn_count`、`last_active_at`，首问填 `title` |
| `messages` | 每轮写 user 与 assistant 两行，按 `(会话, 轮次, 角色)` 复写而非追加 |

assistant 行的 `refusal_reason` 取首段，`payload` 存整份 `TurnResult`。运营回放与评测复盘都读这一份，不再反查能力层。

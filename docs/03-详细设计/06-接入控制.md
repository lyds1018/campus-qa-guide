## 1 中间件

顺序固定，从外到内：

```text
TraceId → Audit → Access → 视图
```

| 中间件 | 职责 | 位置理由 |
| --- | --- | --- |
| `TraceId` | 复用或生成 `X-Trace-Id`，回写响应头 | 后续日志与台账都要用 |
| `Audit` | 每个 `/api/` 请求写一行 `api_logs` | 在鉴权外层，401/403/429 也留痕 |
| `Access` | 身份、角色、限流 | 贴近视图，限流只花在业务请求上 |

只对 `/api/` 生效，静态资源与 Django Admin 走各自的认证。

## 2 身份

系统不接统一身份认证，使用两枚固定 token。

| 身份 | Token | 权限 |
| --- | --- | --- |
| 学生 | `student-demo` | 问答、历史、反馈、清单导出 |
| 管理员 | `admin-demo` | 学生能力 + `/api/ops/*` |

来源：请求头 `X-Demo-Token`；前端另支持 `?token=` 换身份，token 存在 `localStorage`。

识别失败返回 401；非管理员访问 `/api/ops` 返回 403。

## 3 免认证路径

| 路径 | 原因 |
| --- | --- |
| `/api/health` | 容器探活 |
| `/api/docs` | 接口文档页 |
| `/api/openapi.json` | Schema |

其余全部需要 token。

## 4 限流

Redis 固定窗口计数，按分钟分键。窗口精度到分钟，误差最多在边界处翻倍。

| 桶 | 判定 | 额度 |
| --- | --- | --- |
| `chat` | 路径含 `/chat/turn` 或 `/chat/stream` | 20 次/分 |
| `write` | 其余 POST / PUT / PATCH / DELETE | 60 次/分 |
| `read` | 其余 GET | 120 次/分 |

计数键 `acc:rl:{bucket}:{user_key}:{窗口}`，TTL 70 秒。

超限返回 429，带 `Retry-After`（到下一整分钟的秒数）与 `X-RateLimit-Remaining: 0`。Redis 不可用时放行，限流不把服务变成不可用。

## 5 审计

每次 `/api/` 请求一行，只记元数据。

| 字段 | 内容 |
| --- | --- |
| `trace_id` / `user_key` / `role` | 链路与身份 |
| `method` / `path` / `status` / `latency_ms` | 请求事实 |
| `ip` | 优先 `X-Forwarded-For` 首段 |
| `bucket` / `limited` | 命中的限流桶、是否 429 |
| `error` | 响应头 `X-Error` |

不记问句与答案：正文在 `messages` 里，重复存会让敏感内容分散两处。写库失败只记日志，不回传错误。

## 6 接口分层

| 前缀 | 使用者 | 说明 |
| --- | --- | --- |
| `/api/chat/*` | 前端 | 学生端全部能力，需 token |
| `/api/ops/*` | 运营页 | 需管理员 token |
| `/api/kb/*` | 内部 | 知识统计与任务查询 |
| `/api/gw/*` | 内部 | 模型用量、槽位、调用记录 |
| `/api/qa/*` | 内部 | 能力层单点调用，供排障 |
| `/api/orc/*` | 内部 | 编排层直连，绕过接入层 |

内部接口目前同样受 token 保护，没有独立凭据；对外部署需在网络层隔离。

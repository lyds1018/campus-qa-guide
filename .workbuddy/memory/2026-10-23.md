1. **compose 变量插值**：`env_file` 只注入容器环境，不参与 `${}` 插值。原文档在 `environment:` 里写 `${POSTGRES_PASSWORD}`，无 `--env-file` 时求值为空串，**反过来把 env_file 注入的口令洗成空**，PG 直接启动失败。修法：删掉 postgres/minio 的 `environment` 块，容器变量全走 `env_file`；healthcheck 里用 `$$POSTGRES_USER`（容器内 shell 解析）；启动命令统一加 `--env-file .env`。

## 查清「qwen-turbo 无额度」：其实是模型名已下架，429 是伪装

我上一轮说的「qwen-turbo 在本账号无额度」是**错的**，向用户纠正过。真实原因：

**`qwen-turbo` 这个裸模型名已不在百炼模型列表里**。`GET /compatible-mode/v1/models` 返回 178 个模型，含 turbo 的只有 `MiniMax/speech-2.8-turbo`、`z-image-turbo`、`qwen-turbo-2024-11-01`、`qwen-turbo-0919`，**没有裸 `qwen-turbo`**。调用它返回 `429 limit_requests`（"You have exceeded your current request limit"），文案像限流，实际是模型不可用时的兜底。

证据链（三条足以排除频率问题）：
1. 同一把 key 打 `qwen-plus` / `qwen-flash` / `qwen3.8-flash` 全部 **200**；
2. 每次只发**一个**请求，仍 429；
3. 响应里**没有** `Retry-After`、没有 `x-ratelimit-*` 头。
4. 补证：`qwen-turbo-2024-11-01`（列表里存在）返回 **403 access_denied**——说明是「模型在但没授权给默认业务空间」，而不是账号没钱。

**官方错误码对照（关键，以后别再混）**：
- `429 limit_requests` / `Throttling.*` / `insufficient_quota` = **限流**（频率或 TPS 配额，可重试可提额）
- `400 Arrearage` = 真欠费（充值才解决）
- `403 AllocationQuota.FreeTierOnly` = 免费额度耗尽且开了「用完即停」
- `429 BudgetLimitExceeded` = 预算管理到顶
- `404 ModelNotExist` 才是模型名写错；但百炼对下架别名可能回 429，别只信错误码

**改动**：aux 换成 `qwen-flash`（281ms，`json_object` 正常），`.env`、`.env.example` 默认值、`MODEL_PRICING`（0.15/1.5 占位）、P2.md §5.1 表格与 §8.2 价格表、§10.2 排查段全部同步。§5.1 表格曾被外部编辑（可能是 Obsidian 回写）削成 4 列、丢了「备」列与 K2 标记，已按行号用 `.workbuddy/tmp/fix_p2_table.py` 恢复。

- 限流三桶（chat 20 / write 60 / read 120 每分钟），固定窗口 + `Retry-After`；**Redis 挂了要放行**。
- 对外只开 `/api/chat/*`；`/api/orc/*` 是内部面（评测/排障），生产应由 Nginx 只对内网。
- 发布 = 归档同标题旧版 + 发布 + 清 `gw:kb:fingerprint` 与 `qa:terms` 两个缓存；回滚复用同一路径。
- **草稿入库不再归档在版版本**（改了 P1 的 `process_file`）：否则文件刚上传、还没审核，线上知识就黑了；冲突检测也永远找不到"在版对照物"。
- 模型槽位改 DB 表 `model_settings` + 30s 缓存，只覆盖 base_url/model，**密钥永远只在 `.env`**。
- 导出 CSV 由前端提交勾选状态，后端无状态；带 UTF-8 BOM 防 Excel 乱码。
